# TOTP 2FA für Owner (LIN-70) — Umsetzungsplan

**Spec:** `docs/superpowers/specs/2026-11-15-lin-70-totp-design.md` (Design + beschlossene Entscheidungen + advisor-Verfeinerungen A–D).
**Ziel:** TOTP-2FA, Pflicht für Org-Owner (Schonfrist 7 T / 3 Logins), Recovery-Codes, Reset (Owner-UI + Host-CLI), Secrets envelope-verschlüsselt (AppKey-Default via HKDF aus `session_secret`, OpenBAO optional).
**Architektur:** Gate in `App::login` nach Kandidatenwahl, stateless Pending-Token mit Scope (`login`/`enroll`), OAuth-Authorize durch das Login-Gate automatisch gedeckt. Ports→DB→Testkit wie bestehend.
**Tech:** Rust (lineal-app/-db/-api/-server/-jobs/-testkit), neue Crates `sha1`,`base32`,`rand`,`subtle`; Frontend React/TanStack (web/).

## Tasks

**T1 — Migration 5200 (Schema).** `crates/lineal-db/migrations/5200_totp.sql`: Tabelle `user_totp(user_id uuid pk fk user, secret_enc bytea, dek_wrapped bytea, key_backend text, key_version int, confirmed_at timestamptz null, last_used_step bigint null, created_at)`; `user_recovery_code(id uuid pk, user_id, code_hash bytea, used_at timestamptz null, created_at)`; `user_totp_grace(user_id uuid pk fk user, started_at timestamptz, logins_since int not null default 0, created_at)`. Test: `#[sqlx::test]` legt je eine Zeile an (Schema-Smoke).

**T2 — KeyProvider + Envelope-Crypto.** Port `TotpKeyProvider { wrap_dek, unwrap_dek }` in `lineal-app/src/ports/services.rs`. Adapter `AppKeyProvider` (lineal-server): KEK = HKDF-SHA256(`session_secret`, info `"totp-kek-v1"`); Override `LINEAL_TOTP_KEK`. Envelope-Helfer in lineal-app: DEK (XChaCha20-Poly1305) verschlüsselt Secret, KEK wrappt DEK. Tests: Roundtrip; falscher KEK schlägt fehl.

**T3 — TOTP-Core.** `lineal-app/src/usecases/totp/core.rs`: HOTP/TOTP (hmac+sha1), `otpauth_uri`, base32. Deps hinzufügen. Tests: RFC 6238 Appendix B Vektoren; `verify`-Fenster ±1; konstantzeitiger Vergleich (`subtle`).

**T4 — Recovery-Codes.** Erzeugung via CSPRNG (`rand`), Format `XXXX-XXXX`; Hash = keyed HMAC-SHA256; `verify` konstantzeitig. Tests: 10 eindeutige Codes, Hash verifiziert, falscher Code nein.

**T5 — TotpRepo (Port/DB/Fake).** Trait in `ports/repos/totp.rs` (get/upsert user_totp, set_confirmed, set_last_used_step, insert/consume recovery codes, grace get/bump/clear, list owners past deadline). Accessor in `ports/tx.rs`. DB-Impl `lineal-db/src/repos/totp.rs`. Fake in testkit. Test: Repro über Fake + ein `#[sqlx::test]`.

**T6 — Login-Split.** `App::login` → `enum LoginOutcome { Session(Login), TotpRequired{user_id,org}, EnrollRequired{user_id,org} }`. Gate nach `chosen` (auth.rs:194), vor `insert_session`. Audit `login_succeeded` erst bei echter Session; `totp_required`/`enroll_required` als eigene Events. Tests: kein TOTP→Session; aktiv→TotpRequired; Owner-ohne-TOTP-Grace-abgelaufen→EnrollRequired.

**T7 — Pending-Token.** HMAC(`user_id|org|scope|exp`) mit `session_secret`, 5 min, Scope `login|enroll`. mint/verify in lineal-app. Tests: Roundtrip, Ablauf, falscher Scope abgewiesen, Manipulation erkannt.

**T8 — Usecases 2. Faktor + Enrollment.** `verify_totp` (Code **oder** Recovery; Replay-Guard `last_used_step`; Konto-Lockout über `auth_failures` key=user_id; Audit `totp_failed`; Erfolg mintet Session). `enroll_begin` (Secret erzeugen, unbestätigt speichern), `enroll_confirm` (Code prüfen→`confirmed_at`, Recovery-Codes erzeugen, **übrige Sessions widerrufen**), `disable` (Owner gesperrt), `regenerate_recovery`, `status`. Tests: Replay abgelehnt; Lockout nach N; Recovery einmalig; Owner-disable verboten.

**T9 — REST.** `/auth/login` liefert `{totpRequired,pendingToken}` bzw. `{enrollRequired,pendingToken}`; neu `/auth/login/totp` (Token+Code→Session-Cookie). Enroll-Endpunkte akzeptieren Session **oder** `enroll`-Token. `/login?next=` Diskrepanz beheben. Tests: Varianten, CSRF, Cookie erst nach 2. Faktor.

**T10 — GraphQL Account-Mutations.** `totpEnrollBegin/Confirm/Disable/RegenerateRecovery/ResetForUser` + Status in Account-Query (neben `passwordChange`, `graphql/account.rs`). Tests je Mutation + Policy (nur Owner darf `ResetForUser`).

**T11 — Enforcement/Grace.** Owner-Login ohne bestätigtes TOTP: Grace lazy anlegen, `logins_since` erhöhen, Deadline = min(started+7T, 3 Logins); abgelaufen→`EnrollRequired`. Periodischer Job `periodic/totp_grace.rs` widerruft Sessions abgelaufener Owner; Registry eintragen. Tests: 3. Login ok / 4. blockt; Job widerruft nur Fällige.

**T12 — Reset.** Usecase `reset_totp(target)` (nur Owner, auditiert, löscht user_totp+recovery+grace). CLI `lineal-server totp reset --user <email>` (`cli/totp.rs`, `connect(false)`). Tests: Owner darf, Nicht-Owner nicht; CLI-Pfad (Integration).

**T13 — OpenBAO-Provider.** `OpenBaoProvider` (config-gated, Transit encrypt/decrypt). Stubbed-HTTP-Unit-Test für Request/Response-Form. **Nicht** in CI verifizierbar → manueller Test gegen Instanz, nicht als verifiziert melden.

**T14 — E2E OAuth.** Test: anonym `GET /oauth/authorize` → `/login?next=` → `/auth/login` (TotpRequired) → `/auth/login/totp` → Redirect zurück → `authorize` erfolgreich.

**T15 — Frontend.** `auth.ts login()` unterscheidet totp/enroll-Antwort; `login-form.tsx` Zweitschritt-State (OTP + Recovery-Link). `features/settings/account-security.tsx`: TOTP-Sektion (Status, Enroll mit QR, Recovery-Anzeige, Disable/Regenerate, Owner-Reset-für-Nutzer). Enforcement-Banner. `next`-Param. Mit Mockup abgleichen. Vitest + Screenshot-Abgleich wo sinnvoll.
